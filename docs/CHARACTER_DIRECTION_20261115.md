# LIFE 캐릭터 개선안

2026-11-15 · 사용자 첨부 이미지 기준 · **설계 완료, 새 이미지·3D 모델 제작 및 교체는 미실행**.

## 현재 문제

`app/src/Character.tsx`는 실제 3D 모델이 아니라 SVG path·rect·그라디언트로 조립한 캐릭터다. 스카프·장갑·부츠 같은 의상 요소는 있지만 얼굴과 머리카락의 덩어리, 관절의 자연스러운 연결, 천 두께와 주름을 표현하기 어렵다. SVG를 더 복잡하게 만드는 방법만으로 레퍼런스 수준의 조형을 얻기는 어렵다.

첨부 이미지는 회색 재질의 소년 모험가를 정면·측면·사선에서 보여주는 조형 참고다. 회색 자체나 와이어프레임을 서비스 화면에 그대로 넣으라는 요청으로 해석하지 않는다. 특정 캐릭터의 복제보다 비례·재질·조명의 수준을 따른 독자 캐릭터를 만든다.

## 제안하는 외형

- 약 4~4.5등신의 날렵한 소년 모험가. 유아형으로 과장하지 않는 머리, 좁아지는 턱, 자연스러운 큰 눈, 가늘지만 관절이 있는 팔다리.
- 머리카락은 가시 선 대신 방향과 두께가 보이는 큰 덩어리 5~7개. 얼굴·코·눈두덩에 실제 입체 그림자.
- 스카프, 허리에 묶은 겉옷, 손가락 없는 장갑, 접힌 바짓단, 끈 부츠. 부츠 밑창과 천 매듭의 두께를 보이게 한다.
- 색상은 짙은 청록·회갈색·작은 황동 포인트. 피부와 천은 무광, 장난감 같은 강한 플라스틱 광택을 피한다.
- 기본 포즈는 사선 3/4, 편안하게 선 자세와 앞길을 바라보는 표정. 왼쪽 위의 부드러운 주광, 얇은 테두리 빛, 발 아래 접지 그림자.
- 현금 부족이나 채무 상태에 따라 캐릭터를 초라하게 만들거나 슬픈 표정으로 벌주지 않는다.

## 구현 경로

| 경로 | 결과 | 적합한 단계 |
|---|---|---|
| **A. 3D 렌더풍 투명 이미지 (우선 제안)** | 작은 모바일 화면에서도 높은 조형 품질, 기존 SVG 장면에 이미지로 삽입 | 먼저 외형을 만족시키는 단계 |
| B. 같은 모델에서 렌더한 상태별 이미지 | 시선·표정·포즈 변화, 다운로드 크기 관리 필요 | 기본 외형이 확정된 뒤 |
| C. 실제 리깅된 GLB 모델 | 실시간 회전·조명·관절 애니메이션 | 입체 조작이 제품에 필요할 때 |

A는 3D처럼 보이는 2D 이미지다. 실제 모델·회전 기능이 있다고 표현하지 않는다. C는 별도 모델링·UV·재질·리깅과 모바일 성능 검증이 필요하다. 자동 이미지 생성만으로 완성된 GLB가 생긴다고 약속하지 않는다.

## 제작·적용 순서

1. 정면·측면·3/4 시트로 비례와 얼굴을 먼저 맞춘다. 임의의 서로 다른 캐릭터를 상태 이미지로 섞지 않는다.
2. 서비스용은 **한 명만**, 투명 배경·전신·잘리지 않은 손발·접지 가능한 포즈로 별도 제작한다. 참고 이미지의 화면 버튼·문구는 포함하지 않는다.
3. 원본은 고해상도로 보관하고 웹에는 알파 채널을 보존한 WebP/PNG를 사용한다. 다운로드 300KB 안팎을 목표로 하되 실제 시각 품질과 측정으로 결정한다.
4. `Character.tsx`의 `(L,G)` 발바닥 앵커를 보존해 `<image>`로 교체한다. `Home.tsx`의 길 분기·데이터 그래프를 가리지 않게 배치한다.
5. 정적 이미지를 억지로 늘려 숨쉬게 하지 않는다. 처음에는 아주 약한 위치 변화만 쓰고 reduced-motion에서는 멈춘다. 진짜 눈 깜빡임은 검증한 별도 프레임이 있을 때만 넣는다.

## 완료 기준

- 휴대폰 390px·데스크톱에서 얼굴·실루엣이 읽히고 텍스트 및 갈림길과 겹치지 않는다.
- 손가락·눈·부츠가 비정상적으로 합쳐지지 않고, 발이 바닥에 닿는다.
- 투명 가장자리에 흰 테두리가 없고 장면의 빛 방향과 일치한다.
- 새 이미지를 나란히 비교해 외형을 검토한 뒤 교체한다. 현재 UI가 교체됐다고 선행 보고하지 않는다.
