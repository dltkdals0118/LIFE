# 운영 워크플로
여기의 명령은 대화에서 요청할 수 있는 절차명이다. CLI·설치된 슬래시 명령·예약 작업이 아니다.

| 요청 | 선행 입력 | 처리 | 출력/완료 조건 |
|---|---|---|---|
| LIFE 시작/재개 | state/STATUS.md | 최근 기준점·열린 질문 읽기 | 현재 단계와 다음 5~8개 질문 |
| LIFE 조사 [영역] | 해당 intake | 답변·기준일·근거 정리 | 사실 후보·미확인·충돌 |
| LIFE 검증 | 후보 데이터 | 단위·누락·중복 확인 | QUALITY_GATES G1 보고 |
| LIFE 기준점 확정 | G1·사용자 검토 | snapshot 버전 고정 | BASE id·검토 기록 |
| LIFE 경로 설계 | 기준점·목표 | 유지/안정/성장 비교 | 가정·선택·민감도 |
| LIFE 다음 TURN | 경로·직전 종료 | 월별 계산·제약 점검 | 새 SIM 기록 |
| LIFE 실제 기록 | 실제 행동·관측 | 실행 상태 갱신 | execution 기록 |
| LIFE 주간 검토 | 최근 행동 | 장애물·시간·다음 행동 | 다음 주 최대 3개 행동 |
| LIFE 월간 검토 | 잔액·수입·지출 | 대조·기준점 변화 확인 | 새 사실·필요한 재계산 |
| LIFE 저장/인수인계 | 변경 문서 | 검수·상태 갱신·커밋 | 실제 SHA 또는 미완료 사유 |

## 단계 전환
DRAFT → INTAKE → RECONCILE → BASELINE_REVIEW → BASELINE_CONFIRMED → SCENARIO → SIMULATION.
EXECUTION은 사용자가 현실 행동을 선택하면 병행할 수 있다.
핵심 사실이 바뀌면 RECONCILE로 돌아가 해당 시나리오만 outdated 처리한다.
급한 현실 문제는 전체 조사가 끝날 때까지 방치하지 않고 사용 가능한 사실 범위에서 다룬다.

## 질문 운영
질문 목적과 기간을 명시하고 단위를 제시한다. 첫 묶음은 생활·재정·가까운 기한을 확인한다.
답변 후 확인표 → 모순/누락 → 다음 질문 순서로 이어간다.
답변 보류는 상태로 저장한다. 설계 전체를 실패 처리하지 않는다.
외부 자료는 사용자가 지정했거나 요청 범위와 관련 있는 자료만 읽고 근거 최소량을 추출한다.

## 세션 종료
state/STATUS.md를 업데이트하고 새 미확인은 state/OPEN_QUESTIONS.md에 남긴다.
커밋 메시지는 구조·영역·변경 목적만 적는다. 개인 금액·질병·가족 실명을 제목에 넣지 않는다.
세션 중 미확정 답변은 draft로 저장할 수 있다. 기준점 confirmed와 구분한다.
