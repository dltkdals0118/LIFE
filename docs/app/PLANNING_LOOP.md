# 실행과 검토 — 2026-11-15

## 제품 흐름
기준값 입력 → 선택지 편집 → 월별 비교 → 조건 확인 후 채택 → 행동 실행 → 장애물과 실제 결과 검토.
앱의 `실행과 검토`에서 모두 접근한다. 새 사용자는 JSON 파일 없이 시작한다.

## 데이터 경계
- decisions는 기존 schemaVersion 1에 기본값 []로 추가한다. 기존 데이터베이스 변경은 필요하지 않다.
- 채택은 실제 관측을 변경하지 않는다. 당시 sim과 picks, modelVersion, 목표, 재검토일, 조건, 연결 행동 ID를 별도로 보존한다.
- 전체 조합의 실행 계획은 동시에 하나만 활성화한다. 같은 자원을 독립된 조합 여러 개에 배정하지 않기 위한 초기 범위다.
- 기준값 수정은 사용자 입력을 통해서만 수행한다. 최신 현금 관측은 갱신 안내를 만들고 자동 대입하지 않는다.
- 결과 비교는 당시 예측 기간에 속하는 종료된 월의 월말 잔액으로만 한다. 일중 잔액과 월말 예측을 비교하지 않는다.
- 백업·동기화 충돌 비교에 결정과 일기 개수를 포함한다. 모든 기기의 앱을 새로고침한 뒤 사용한다. 구버전 클라이언트는 새 필드를 알지 못한다.

## 계산과 표현
- 월수지 + 월별 선택 증감으로 조건별 결과를 계산한다. 각 선택의 시간 효과도 시작월부터 적용한다.
- 시간 부족이 있는 조합과 가용시간 미입력 조합은 채택을 차단한다.
- 현금 부족 조합은 부족월을 보여주고 사용자가 검토할 수 있다. 채택은 안전성 인증이 아니다.
- 기준월의 부분 기간과 월중 납부일, 일시 비용은 계산하지 않는다. 기준 현금이 계산 시작월 직전 월말에 해당하도록 사용자가 확인한다.
- '최선' 대신 '현금 증가액이 큰 조합'. 인생 전체 효용을 최적화한다고 주장하지 않는다.
- A/B/C를 난이도 순서로 추정하는 추천은 제거했다. 완료 이력이 없는 신규 플랜은 idle 경보를 내지 않는다.

## 검증
단위/DB 테스트, 기존 모바일·PC E2E, 신규 빈 공간에서 입력→채택→실행→실제 비교→재접속 E2E.
GitHub Actions에서 브라우저 검증을 수행한다. 로컬 실행환경은 Chromium의 Unix socket 생성을 제한한다.

## 후속 범위
상호배타 선택 자동 검증, 거래 원장 기반 월중 현금 모델, 분야별 목표의 가중 비교, 기기 간 필드 단위 병합은 미구현.
이번 버전은 사용자가 실행 전제·중복 절감액·일정 충돌을 확인한다. 예측 성공률을 생성하지 않는다.
