# LIFE 전체 설계 v0.1
## 1. 프로젝트 정의
LIFE는 장기적으로 유지하는 개인 의사결정 프로젝트다.
입력은 현실 자료·자기보고·목표, 출력은 검토 가능한 기준점·선택지·행동·갱신 이력이다.
인생의 미래를 맞히는 예언이나 의료·재무 점수로 사람을 평가하는 시스템이 아니다.

## 2. 성공 기준
- 현재의 돈·시간·의무가 출처와 함께 설명된다.
- 무엇을 모르는지와 그것이 결정에 주는 영향을 찾을 수 있다.
- 목표별 비용·기한·필수 조건을 추적할 수 있다.
- 동일한 기준점과 가정으로 계산한 결과를 재현할 수 있다.
- 가상 결과와 실제 생활 기록이 섞이지 않는다.
- 새 대화에서도 마지막 상태와 다음 행동을 복원할 수 있다.
- 기록 부담이 실제 생활을 방해하면 항목·주기를 줄일 수 있다.

## 3. 계층과 책임
| 계층 | 입력 | 출력 | 정본 |
|---|---|---|---|
| 조사 | 답변·정리된 근거 | 사실 후보·질문 | intake, reality |
| 검증 | 후보·단위·날짜 | 충돌·누락·사용 가능 범위 | docs/QUALITY_GATES.md |
| 기준점 | 검토한 사실 | 버전 고정 스냅샷 | reality/baselines |
| 모델 | 기준점·가정 | 월별 돈·시간 변화 | docs/FINANCE_MODEL.md |
| 시나리오 | 모델·목표 | 경로별 결과·전환 조건 | simulation |
| 실행 | 사용자가 선택한 행동 | 관측·주간 회고 | execution |
| 운영 | 위 전체 | 현황·결정·인수인계 | state, decisions |

## 4. 주요 객체의 연결
source_id → fact_id → baseline_id → scenario_id → turn_id.
goal_id → action_id → observation_id.
decision_id는 선택에 사용한 baseline_id·scenario_id와 선택 이유를 연결한다.
현실 변화는 새 fact_id/기준점 버전으로 기록하고 기존 시나리오에는 outdated 표시를 한다.
시나리오가 현실을 직접 수정하는 경로는 두지 않는다.

## 5. 조사 트랙
1. 생활·기한·의무
2. 재정·부채·필요 자금
3. 경력·실력·시장성
4. 직장 내 입지·이직 조건
5. 몸·마음·회복
6. 가정·관계·지원
7. 시간·습관·실행
8. 목표·꿈·가치
9. 포커 등 변동성 큰 취미·수입 활동(해당할 때)

고정 순서는 아니다. 급한 지출·퇴사 기한·생활 기능 저하처럼 결정에 영향이 큰 사안을 먼저 조사한다.

## 6. 의존 관계
- 지출·상환·수입 없이는 현금 부족 시점을 확정하지 않는다.
- 가용시간·회복 상태 없이는 부업·공부 계획의 실행성을 판단하지 않는다.
- 실적·수요 근거 없이는 미래 단가·이직 보상을 확정하지 않는다.
- 가족 의무·주거 조건 없이는 이동·퇴사 선택지를 평가하지 않는다.
- 목표의 우선순위 없이는 하나의 '최적 경로'를 고르지 않는다.
빈 항목이 있다고 전체 설계를 중단하지 않는다. 영향을 받는 결론만 조건부로 남긴다.

## 7. 설계 원칙
정본은 한 곳에 둔다. 다른 문서는 복제 대신 링크한다.
인생 전체를 단일 점수로 합치지 않는다. 자금 안전성·건강 기능·관계·성취·자율성의 교환을 나란히 보여준다.
역할 수와 파일 수는 품질 지표가 아니다. 실제 입력·출력·검수 책임이 있는 단위만 둔다.
사용자 확인은 현실 사실과 가치판단에 집중하고, 통상적인 문서 수정은 진행한다.

## 8. 초기 구현 경계
이 릴리스: 문서 기반 운영 체계, 조사 은행, 데이터 명세, 템플릿, 개발·검증 명세.
후속 구현: 자료 검증기 → 재무 계산기 → 시나리오 실행기 → 로컬 대시보드.
은행 자동연결·의료 진단·포커 전략 최적화·공개 사이트 배포·예약 알림은 기본 범위에 포함하지 않는다.
자동화가 필요해지면 목적과 데이터 흐름부터 설계한다.

## 9. 참고 시스템에서 채택한 것
WACUS_Agents의 역할 분리, 입력/출력 계약, 작업과 검수의 분리, 상태 정본, 재개 문서를 채택했다.
해당 저장소는 PC 정본의 엔진 사본이므로 수정하지 않았다.
LIFE는 GitHub 저장소 자체를 정본으로 사용한다. WACUS의 고객 구조·점수 가중치·모델명·병렬 실행 규칙은 복제하지 않는다.
참고 파일과 근거는 decisions/ADR-001-architecture.md에 기록한다.
