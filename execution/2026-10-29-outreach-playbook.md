# G2 아웃바운드 운영 절차 — 2026-10-29

작성: WACUS · 근거 [90일 실행 계획](2026-10-29-plan-90days.md) · 기준점 [BASE-20261028-v1](../reality/baselines/BASE-20261028-v1.md)

**이 문서는 절차다. 명단도 지시도 아니다.**
90일 계획이 "아직 안 정한 것"으로 남긴 **대상 선정 방법**과 **접촉 운영 방법**만 채운다.
누구에게·언제·어디서 보낼지는 **본인이 정한다.** 비워 둔 칸은 8번 절에 모아 뒀다.

## 왜 명단보다 절차가 먼저인가
첫 거래는 콜드 아웃리치다(FACT-0165). 인맥도 채널도 없으니 지름길이 없고,
**접촉 수가 유일한 레버다.**

레버를 돌리려면 **건당 비용이 작아야 한다.** 한 곳에 3시간이 들면
영업 주 3~5시간(FACT-0166)으로 주 1~2곳이고, 30분이면 주 6~10곳이다.
**이 문서가 하는 일은 그 건당 비용을 깎는 것 하나다.**

## 1. 생산 체인 — 실재하는 것만 적는다
`C:\Users\owner\Agents` 워크스페이스에 아래가 **실제로 있다** (근거: `직접확인` 2026-10-29, 파일 목록 확인).

| 단계 | 도구 | 나오는 것 |
|---|---|---|
| 노출 관측 | `/rank` | 네이버 웹 탭·통합검색에서 그 사이트가 **어느 블록**에 걸리나 |
| 수집 | `python work/_capture.py <프로젝트> --from-brief` | 렌더 DOM·head(canonical·robots·구조화 데이터)·캡쳐·sitemap |
| 진단 | `/live-review` | 관점별 검수 리포트 + 우선순위 정렬된 통합 리포트 |
| 전달본 | `templates/seo_report/` (`skeleton.html` · `build_request.py`) | 한 항목 = 한 장, "지금 → 이렇게" 형식 HTML 한 벌 |

**이것이 "에이전트가 진단서를 거의 공짜로 만든다"(FACT-0163)의 실체다.**
사람 손이 가는 구간은 **대상 URL 지정 · 결과 검토 · 보낼 문장**뿐이다.

**다만 1건에 실제로 몇 시간이 드는지는 모른다 — 빈칸이다.**
ASM-0017(건당 10시간)은 *유상 납품* 추정이고 무상 진단서는 그보다 짧을 것이다(추정).
→ **W1 에 1건을 끝까지 돌려 실측한다.** 그 숫자가 W2 배치 크기를 정한다.

### 섞지 않을 것
그 워크스페이스에는 **회사 고객 프로젝트가 들어 있다.**

- 도구(엔진)는 재사용한다. **고객 데이터·산출물은 개인 영업에 쓰지 않는다.**
- 개인 영업용은 **별도 프로젝트 폴더**에서 돌린다.
- **회사 작업물을 포트폴리오로 내보내면 그 자체가 겸업 발각 경로다**(근거: `추정` — FACT-0149 겸업 금지 + 산출물 출처가 회사).
  → 그래서 **무상 진단서가 포트폴리오를 대신한다.** 새로 만든 것이라 출처 문제가 없고,
  외주 경험 부재(FACT-0152)를 **결과물로 대신 증명**하는 방법이기도 하다.

## 2. 대상 선정 — 관측할 수 있는 조건만
"좋은 고객"을 정의하지 않는다. **스크리닝으로 걸러지는 조건**만 쓴다.

| # | 조건 | 왜 | 무엇으로 보나 |
|---|---|---|---|
| S1 | 홈페이지가 **있다** | 진단 대상이 있어야 제안이 성립한다 | 접속 |
| S2 | 검색에서 **잘 안 보인다** | 개선 여지가 제안의 근거가 된다 | `/rank` 통합검색 블록 위치 |
| S3 | **고칠 수 있는 결함이 실제로 있다** | 없으면 보낼 말이 없다 | `_capture.py` 관측값 (canonical·robots·H1·구조화 데이터) |
| S4 | 의사결정자가 **가깝다** | 소규모일수록 대표가 직접 읽는다 | 사이트 규모·대표 연락처 노출 |
| S5 | 대행사가 **이미 붙어 있지 않다** | 붙어 있으면 교체 영업이고 길어진다 | 푸터·소스 흔적 — **`추정`에 머문다** |

**하드 컷 (제외)**
- 현 직장의 고객·제안 중인 잠재고객 — 이해충돌이고 발각 경로다
- 접촉 기록이 회사에 남는 경로(회사 메일·회사 계정) — **결정은 본인 몫이고, 위험만 여기 적어 둔다**

**업종·지역은 비워 둔다.** 관측 하나만 적는다:
**S3 를 가장 싸게 확인할 수 있는 업종일수록 접촉 단가가 낮다.**

## 3. 한 건의 흐름
```
0) 대상 1곳 선정 (S1~S5)
1) /rank        → 노출 관측. 웹 탭과 통합검색을 구분해서 적는다
2) _capture.py  → 수집. head·헤딩·구조화 데이터
3) 결함 2~3개만 고른다      ← 전부 적지 않는다. 읽는 사람은 대표·원장이다
4) 전달본 1벌 생성 (한 항목 = 한 장)
5) 보낸다 (경로·문장은 본인 결정)
6) 대장에 적는다 → trackers/G2-outreach.md
```

**3)에서 멈추는 것도 정상이다.** S3 결함이 안 나오면 그 대상은 버린다 —
버린 것도 기록한다. **접촉 가능 대상의 밀도**를 알게 되고, 그게 명단 크기를 정한다.

## 4. 문안 — 구조만 정하고 문장은 본인이 쓴다
| 칸 | 넣는 것 | 넣지 않는 것 |
|---|---|---|
| 1 | 그 사이트에서 **직접 본 관측 1~2개** | 일반론·업계 트렌드 |
| 2 | 그것이 **무엇을 잃게 하는지** — 추정이라고 밝힌 추정 | 수치 보장("3개월 내 1위") |
| 3 | **이미 만들어 둔** 무상 진단서 | "무료 상담 가능합니다" |
| 4 | 다음 행동 **하나** (회신 또는 통화) | 선택지 여러 개 |

**금지 — 우리 쪽 리스크다**
- 순위·매출 **보장**. 표시광고 리스크이고 첫 거래에서 가장 비싸게 돌아온다
- 의료 대상이면 **효과·최상급 표현 금지**(의료광고법). 우리가 쓸 자격이 없는 내용은 비워 둔다
- 상대 사이트를 **깎아내리는 표현** — 그 사이트를 만든 사람이 읽는 사람일 수 있다

## 5. 운영 — 배치와 회신
| | |
|---|---|
| 한 배치 | **5곳**을 제안한다. 1곳이면 표본이 안 되고 20곳이면 회신 처리에 묻힌다 |
| 간격 | 배치 간 3~4일 — 회신을 보고 문안을 고친다 |
| 회신 없음 | 짧게 **1회만** 재확인. 2회 이상 하지 않는다 |
| 회신 있음 | 통화·미팅으로 넘긴다. **여기부터는 절차가 아니라 대화다** |
| 거절 | 사유를 대장에 한 줄. **사유가 레버다** — '필요 없다'·'예산 없다'·'이미 맡겼다'는 서로 다른 수정으로 이어진다 |

**한 번에 하나만 바꾼다.** 배치 2회(10곳)에 회신 0건이면 **대상이 아니라 문안을 먼저 고친다** —
둘을 같이 바꾸면 무엇이 틀렸는지 알 수 없게 된다.
